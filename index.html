A free music player for your own music

Spinet plays what is on your device, what is on a server you run, and what is online, and treats the three as one library. No ads, no subscription, no sign-in.

Plays what you already have

A local copy first, your server next, online last. Nothing is fetched twice.

Syncs between devices

Playlists, likes and play counts sync through your own server.

Songs keep their details

Downloads carry real title, artist and cover art, not just a filename.

What it does

One library

Search runs across every source you enable and merges the results. Playback prefers the copy you already hold: device, then your server, then online.

Search your library

Filter any list by title or artist, and search your whole server library rather than one folder at a time.

Correct covers and tags

Artwork and metadata come from iTunes, with karaoke and tribute recordings rejected rather than matched, and a re-fetch that ignores whatever a bad match left behind.

Background playback

Keeps playing when the phone is locked, with notification and lock-screen controls. On the desktop: a mini player that stays on top, taskbar controls and media keys.

Playlists

Create them, import from CSV, drag to reorder, swap in alternate versions of a song. A playlist never holds the same song twice.

Updates

The app checks GitHub for a new release, verifies the download against a published SHA-256, and asks before installing anything.

Run your own server

Optional, and free. A small self-hosted library that stores your music and serves it back to every device you use. Upload from the phone, browse folders as playlists, stream, delete. One docker compose up.

Play the setup video

Plays here from YouTube once you press play. The written steps are in the server repo.

  1. Get a machine

    An Oracle Cloud Always Free instance costs nothing and is enough. Any box that runs Docker works.

  2. Get a hostname

    A free Duck DNS name is fine, and the certificate is issued automatically either way. No domain purchase needed.

  3. Start the stack

    Clone the repo, set your domain in .env, and run docker compose up -d.

  4. Point the app at it

    Open Settings > My Server, enter your address, choose HTTPS or HTTP and press Save. Every device you do this on shares the same library.

Questions

Is it really free?

Yes. No ads, no subscription, no account, no paid tier. It is GPLv3 software, so you can read the code, change it, and share it.

Do I need a server?

No. Without one Spinet still plays music on your device and from any sources you add. The server is what lets your library, playlists, likes and play counts follow you between devices.

Where does the music come from?

Your own server, a folder on your device, and any sources you add yourself as extensions. You decide what is installed and what is turned on.

Can I use more than one server?

Yes. Add as many as you like under Settings, My Servers, for example one for each person in the family, and put them in the order you want. A song plays from the first server that has it, and if that server isn't answering, the next one is used. Uploads and syncing go to the server at the top.

Can I make my own extension?

Yes. Extensions are small Kotlin projects, and there is a step-by-step guide with a working example to start from.

Which music files does it play?

On Android: MP3, M4A, AAC, FLAC, OGG, Opus, WAV and AIFF. On Windows: MP3, M4A, AAC, WAV and AIFF. FLAC, OGG and Opus files show up in your library on Windows but don't play there yet; convert them to MP3 or M4A, or play them on your phone. Your own server stores all of these formats.

Can I download songs?

Spinet can save audio from the sources it resolves, with title, artist and cover art embedded. Downloading copyrighted material may breach a provider's terms or your local law. That choice, and the responsibility for it, is yours. Spinet is a tool, not a licence.

Does it track me?

No analytics, no telemetry, no account. The app only contacts the sources you switch on, your own server, the iTunes Search API for covers and song details, and GitHub when it checks for an update. This website has no analytics and sets no cookies of its own. It asks GitHub for the latest release so the download buttons stay current, and loads the setup video from YouTube only if you press play.

Why is the Android build sideloaded?

It is distributed as an APK from GitHub releases rather than a store listing. Android will ask you to allow the install once; updates after that are handled inside the app.
